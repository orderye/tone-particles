# 宿主接入指南

语气助词 Skill 除了能作为 Skill 包直接安装，还可以被任意宿主应用以
「系统提示词注入」的方式使用（PRD 8.1 的方案 B）。本指南说明宿主需要做什么。

仓库里的 `integrations/` 提供了一份可直接参考的实现：Python 库
`host_adapter.py`、给非 Python 宿主用的 JSON over stdio `host_cli.py`，
以及一个能跑起来的 `demo_loop.py`。

---

## 一、宿主要做的两件事

**每轮请求前**，调一次 `next_turn()`，把返回的 `system_suffix` 追加到 system
prompt 末尾。

**模型回复后**（可选），调一次 `observe()`，拿到密度与硬规则的回检结果，
用于埋点或质量告警。

除此之外，宿主不需要理解助词、密度、颜文字这些概念——选风格、拼提示词、
维护历史都在适配层里完成。

---

## 二、调用时机与拼接位置

```
用户输入
   │
   ├─→ 适配层 next_turn()  ──→  system_suffix
   │                              │
   └──────────────────────────────┴──→  system = 宿主原有 system + system_suffix
                                              │
                                        调用大模型
                                              │
                                        模型回复
                                              │
                                        适配层 observe()  ──→ 回检结果
```

`system_suffix` 是一段 Markdown，结构固定：

```
# 本轮语气指令（tone-particles 生成）
- 模式：融合
- 风格：S09 傲娇（主，权重 4，67%）、S04 邻家（副，权重 2，33%）
- 密度：standard（×1），参考 1.7–2.3 次/百字
- 融合向量：温暖 6.1 / 能量 4.9 / …

## 通用规则（优先于风格）
## 融合规则
## 主风格全文（S09 傲娇）
## 副风格素材（S04 邻家，33%）
## 输出前检查
```

**拼接位置**：追加到 system prompt 的**末尾**。通用规则与安全边界写在最前面，
风格全文在后面——这样提示词的优先级顺序和内容的强调程度一致。

**不要**把 `system_suffix` 放进 user message，也不要放在 system 的最前面：
它含有大量「本轮语气指令」式的元信息，放在前面容易被模型当成用户诉求。

---

## 三、历史归属

历史（最近用过哪些风格）由**适配层持有**，落在 `config/tone-history.json`。

- 适配层在每次抽样时自动读历史、追加本轮结果。
- 宿主不需要管历史，也不需要在 prompt 里带历史。
- 换会话时调 `begin_session()`，它会载入磁盘上的历史并重置轮次计数。

如果宿主是多用户应用，**每个用户一份 config 与 history**：

```python
host = ToneHost(
    config_path=f"/var/lib/myapp/users/{user_id}/user-config.json",
    history_path=f"/var/lib/myapp/users/{user_id}/tone-history.json",
)
```

---

## 四、缓存策略

`system_suffix` 在同一轮风格与同一密度档下是稳定的。宿主可以按
`(style_id, members, density)` 做缓存，避免重复拼装——拼装本身开销不大，
但缓存能省掉反复读风格文件的 I/O。

**不要跨用户缓存**：同一个风格在不同用户的上下文里含义相同，但注入位置不同；
缓存键里带上用户或会话标识更稳妥。

历史文件本身已经做了截断（只保留最近 50 条），不会无限增长。

---

## 五、错误处理

适配层用中文错误消息，都是可预期的配置问题：

| 情况 | 行为 |
| --- | --- |
| 配置文件不存在 | `onboarding_required` 为 True，`next_turn()` 仍会返回内容（按默认配置） |
| 配置 JSON 非法 | 抛 `SystemExit`，消息形如「配置文件不是合法 JSON：…」 |
| `mode` 非法 | 抛 `SystemExit`，消息形如「mode 必须是 […] 之一，当前为 'zzz'。」 |
| 风格 id 不存在 | 抛 `SystemExit`，消息形如「未知风格 id：S99。可用：S01, …」 |
| 未知配置键 | 抛 `SystemExit`，消息形如「未知配置键：denstiy。可用：density, …」；文件不变 |
| 配置写入失败（只读目录、磁盘满等） | 抛 `SystemExit`，旧配置保持原样，**不会**返回「保存成功」 |
| 并发更新冲突 | 在 `config/user-config.json.lock` 上等待（默认 5 秒）；超时抛 `SystemExit` |
| 历史文件写不进去 | 静默忽略，不影响本轮对话 |

宿主侧建议把 `SystemExit` 当成普通异常捕获，转成用户可读的提示，不要让整个
服务挂掉。JSON CLI 版本已经把异常包成 `{"ok": false, "error": "..."}`。

### 配置写入的语义

`update_config()` 走的是共享核心里同一套「读—改—写」：

1. 取 `config/user-config.json.lock` 的跨进程独占锁（拿不到就报错，不静默覆盖）。
2. **在锁内重新读取**当前配置——不在锁外读，避免并发时用一份旧读覆盖掉别人
   刚写入的字段。
3. 只合并这次明确请求的字段，其余字段原样保留。
4. 写前校验（非法值直接拒绝）→ 原子写入（临时文件 + fsync + 替换）→
   写后重新读取校验。

多用户宿主请给每个用户单独的 `config_path` / `history_path`，或用
`ToneHost(user_dir="/var/lib/myapp/users/<id>")` / `TONE_PARTICLES_USER_DIR`
指定各自的目录——默认路径是 skill 目录下的 `config/`，多人共用会串线。

## 六、配置 schema

配置是一份 JSON。字段口径的**单一来源是 README 的「配置」一节**，本文只列宿主接入会用到的字段（PRD 7.4 是 v0.1 阶段的设计草案，已过时）。实际写全一点是这样：

```json
{
  "version": 1,
  "mode": "blend_random",
  "styles": [
    { "id": "S09", "weight": 3 },
    { "id": "S04", "weight": 2 },
    { "id": "S17", "weight": 1 }
  ],
  "density": "standard",
  "switch": {
    "granularity": "per_message",
    "no_repeat_window": 3,
    "locked": false,
    "turns": 3
  },
  "scene_adapt": true,
  "kaomoji": { "enabled": false, "level": "light" },
  "emoji": "style_default",
  "paused": false,
  "variants": { "S20": "gentle" }
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `version` | 整数 | 配置版本，升级时做迁移 |
| `mode` | `single` / `blend` / `rotate` / `blend_random` | 四种运行模式 |
| `styles` | `[{id, weight}]` | 风格池，权重为正整数；`single` 模式只取第一项 |
| `density` | `light` / `standard` / `strong` | 密度档位，系数 0.5 / 1 / 1.5 |
| `switch.granularity` | `per_message` / `per_n_turns` / `on_topic_change` / `per_session` | 什么时候换风格 |
| `switch.no_repeat_window` | 0–10 | 最近多少条内不重复同一风格，默认 3 |
| `switch.locked` | 布尔 | 锁定当前风格，不重新抽样 |
| `switch.turns` | 1–20 | `per_n_turns` 时每几条切一次，默认 3 |
| `scene_adapt` | 布尔 | 是否按场景自适应降档；危机处理始终生效，不受此开关影响 |
| `kaomoji.enabled` | 布尔 | 颜文字开关，默认关闭 |
| `kaomoji.level` | `light` / `normal` | 颜文字频率档位 |
| `emoji` | `style_default` | emoji 使用策略 |
| `paused` | 布尔 | 暂停语气，此时 `next_turn()` 不注入任何风格 |
| `variants` | `{风格 id: 子模式}` | 目前只有 S20 老师支持 `gentle` / `strict` |

**控制指令落到配置上**。用户说「换成傲娇」「语气浓一点」「暂停语气」这类话时，
宿主（或宿主里的模型）把意图翻译成对配置的修改，再调 `update_config()`：

```python
host.update_config({"mode": "single", "styles": [{"id": "S09", "weight": 1}]})
host.update_config({"density": "strong"})
host.update_config({"paused": True})
host.update_config({"switch": {"locked": True}})
```

## 七、场景自适应怎么落

**先说结论：现在判断已经在适配层里做完了，而且是确定性的。**

适配层按一组可审计的文本规则判断这一轮的场景（代码 / 表格 / 高风险 / 正式写作 /
报错排查 / 情绪低落 / 非中文 / 危机），并把结果写进注入的提示词里。规则、优先级
与 reason code 见 [`语境策略与场景优先级.md`](语境策略与场景优先级.md)。

```python
# 自动判断（受配置里的 scene_adapt 控制）
turn = host.next_turn("帮我看看这段代码报错了")

turn["context"]["reason_code"]   # "code"
turn["context"]["reason"]        # "检测到代码或排障任务：正文保持中性……"
turn["density"]                  # "light"
```

**宿主要有更准的场景信息时，用显式元数据覆盖自动检测：**

```python
turn = host.next_turn(user_input, topic=topic, context={"scene": "code"})
```

`context` 是可选参数，旧调用方式照旧可用。

**危机不可覆盖。** 检测到危机信号时适配层直接返回 `active: False`、不注入任何
提示词、不抽样、不写历史——危机规则不接受宿主的显式元数据覆盖，也不受
`scene_adapt: false` 影响。危机信号的判定见 `references/safety.md` 第 5 节：
先关闭风格，再用平实语言回应，直接询问安全，并给出求助渠道（120 / 110 / 12356）。

**如果宿主不使用适配层**（自己拼 system prompt），那场景判断仍然要宿主自己做：
按 `SKILL.md` 的「场景自适应」表降档，并把降档档位传给 `next_turn` 的 `density`
参数：

```python
# 用户在问代码或命令 → 降到轻档
turn = host.next_turn(user_input, topic=topic, density="light")
```

密度参数优先于语境策略的自动判断——宿主显式给的档位是宿主的最终决定。

## 八、无法运行代码时的降级（PRD 7.6）

宿主环境如果不允许执行 Python，可以按 PRD 7.6 在提示词内近似执行：

- **随机**：用「会话轮次号 + 去重窗口」取模选风格，且不与上一条相同。
- **融合**：直接把主风格与副风格的提示词按权重拼进 system。
- **密度检测**：改为离线抽检。

对应的静态素材都在 `styles/` 与 `references/` 里，纯文本读取即可。

## 九、非 Python 宿主

用 `integrations/host_cli.py`，每行一个 JSON 请求、一行一个 JSON 响应：

```bash
printf '%s\n' \
  '{"op":"next_turn","user_input":"帮我安排明天的日程","topic":"日程"}' \
| python3 integrations/host_cli.py --config /path/user-config.json --history /path/history.json
```

支持的操作：

| op | 入参 | 返回 |
| --- | --- | --- |
| `begin_session` | — | 载入历史、重置轮次 |
| `next_turn` | `user_input`、`topic?`、`density?`、`context?` | system 后缀与本轮风格 |
| `observe` | `reply`、`style?`、`density?` | 密度与规则回检结果 |
| `set_config` | `patch` | 写入后的完整配置 |
| `get_state` | — | 当前轮次、当前风格、最近历史 |
| `catalog` | — | 21 个风格与 6 个分组 |

`next_turn` 的 `context` 是可选的语境元数据（如 `{"scene": "code"}`），用来覆盖
适配层的自动场景判断；不给就按确定性规则自动判断。

宿主也可以长期起这个进程，用管道持续交互——它会一直读到 stdin 结束。
