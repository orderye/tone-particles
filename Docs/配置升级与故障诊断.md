# 配置升级、回滚与故障诊断

面向使用者的操作手册：配置怎么升级、出问题怎么看、怎么退回。

---

## 一、配置版本与兼容性

| 项目 | 现状 |
| --- | --- |
| 配置 schema 版本 | `version: 1` |
| 当前 skill 版本 | 见根目录 `VERSION` |
| 是否需要迁移 | **不需要**——本次升级没有新增配置字段 |
| 旧配置可否直接读 | 可以，直接读 |

`config/user-config.json` 的字段与 0.2.x 完全一致：

```json
{
  "version": 1,
  "mode": "blend_random",
  "styles": [{"id": "S09", "weight": 3}],
  "variants": {},
  "density": "standard",
  "switch": {"granularity": "per_message", "no_repeat_window": 3, "locked": false, "turns": 3},
  "scene_adapt": true,
  "kaomoji": {"enabled": false, "level": "light"},
  "emoji": "style_default",
  "paused": false
}
```

新增的语境策略**没有**新配置项：它复用既有的 `scene_adapt` 开关
（`false` = 关闭自动分类，危机规则始终生效），强度上限复用既有的
`density` 三档。

### 迁移规则

`scripts/_core.py` 的 `migrate_config()` 按 `version` 字段迁移：

- `version` 缺省视为 1；
- `version` 高于当前支持的版本 → 直接报错「配置版本 N 高于当前支持的 M，请先升级 skill」，
  **不会**尝试猜；
- `version` 小于等于当前版本 → 补齐缺省字段，保留已有值。

迁移是幂等的：同一份旧配置连续迁移两次，结果相同。

## 二、写入语义（读这一段再改配置）

所有写入路径（宿主 `update_config()`、MCP `set_user_style`）走同一套「读—改—写」：

1. **原子写入**：同目录临时文件 → flush + fsync → 原子替换。写到一半被杀，
   旧配置保持完整可读，不会留下半截 JSON。
2. **跨进程加锁**：更新期间持有 `config/user-config.json.lock`。两个进程同时改
   同一份配置时，后一个等待（默认 5 秒），拿不到锁就报错，不静默覆盖。
3. **写前校验**：非法值（枚举错、权重非正、风格 id 不存在）直接拒绝，旧文件
   字节不变。
4. **写后校验**：写完重新读取并归一化，确认落盘内容仍可读。写入失败不会返回
   「保存成功」。
5. **未知字段**：默认保留并向 stderr 告警（不静默丢弃）。
6. **越界数值**：`switch.no_repeat_window`（0–10）与 `switch.turns`（1–20）会被
   夹到合法区间，并产生一条告警。
7. **权限**：用户配置写为 `0600`。

## 三、故障诊断

### 配置文件读不了

```bash
python3 -c "
import sys; sys.path.insert(0, 'scripts')
import _core
cfg = _core.load_config('config/user-config.json')
print(cfg['mode'], [s['id'] for s in cfg['styles']])
"
```

报错信息的含义：

| 报错 | 含义 | 怎么办 |
| --- | --- | --- |
| 找不到配置文件 | 路径写错，或还没做过导入向导 | 用 `--config` 指对路径；或按 `references/onboarding.md` 走导入向导 |
| 配置文件不是合法 JSON | 文件被截断或手工改坏了 | 见下面「修复损坏的配置」 |
| 配置版本 N 高于当前支持的 M | skill 比配置旧 | 先升级 skill |
| 配置校验未通过：未知风格 id | 配置里引用了不存在的风格 | 改成 `S01`–`S21` 之间的 id |
| 配置校验未通过：variants.S20 必须是 … | 子模式值非法 | 改成 `gentle` 或 `strict` |
| mode 必须是 … 之一 | 模式写错了 | 四个合法值：`single` / `blend` / `rotate` / `blend_random` |

**诊断日志只写错误类别、路径类别、请求 id 这类必要内容**——配置内容与用户对话
不会进日志。

### 修复损坏的配置

1. **先备份**：`cp config/user-config.json config/user-config.json.bak`
2. 看一眼坏在哪：
   ```bash
   python3 -c "
   import json
   try:
       json.load(open('config/user-config.json', encoding='utf-8'))
       print('JSON 合法')
   except json.JSONDecodeError as exc:
       print('损坏位置：', exc.lineno, exc.colno, exc.msg)
   "
   ```
3. 手动改那几行；改不动就退回默认：
   ```bash
   cp config/defaults.json config/user-config.json
   ```
   **这一步会丢掉用户的配置**——只在备份已确认的前提下做。
4. 历史文件 `config/tone-history.json` 与配置独立，坏了不影响使用：删掉即可，
   下次抽样会重新开始。

### 并发写入报「等待配置锁超时」

说明另一个进程正拿着锁写同一份配置。等几秒重试；持续超时说明那个进程可能卡住
或已经异常退出——锁由操作系统在进程退出时自动释放，所以「进程死了锁不会永远
占着」，但正在跑的进程卡住时会占着。此时确认没有别的进程在写，再重试。

### 迁移失败怎么办

迁移失败时原文件保持可恢复：迁移在内存 / 临时对象上完成，校验通过后才原子替换。
所以「迁移失败」等于「配置没被动过」。修好报错里指出的字段再试即可。

## 四、不联网的检查与修复

本项目全部检查都在本地完成，不访问网络、不需要密钥：

```bash
python3 tools/selfcheck.py                    # 配置 / 风格一致性 / CLI / 全部测试
python3 eval/validate_cases.py                # 评测用例结构
python3 .github/workflows/ci_checks.py config # 配置与 schema 校验
python3 .github/workflows/ci_checks.py smoke  # CLI 冒烟
python3 tools/package.py --verify             # 打包与供应链校验
```

**不会**自动覆盖用户数据：任何修复动作都要显式执行，且先备份。
