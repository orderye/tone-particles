## 回滚

### 代码回滚

```bash
git log --oneline -5                 # 找到最后一个已知稳定的 commit
git revert <commit>..HEAD            # 逐个撤销本次改动（推荐，保留历史）
# 或者：确认工作区干净后再
git reset --hard <commit>           # 只在共享分支外、且已确认干净时使用
```

不要对共享分支执行未经授权的 `reset --hard`、强制推送或破坏性清理。

### 配置回滚

本次升级**没有新增配置字段**，不需要迁移，旧配置直接可读：

```bash
python3 -c "
import sys; sys.path.insert(0, 'scripts')
import _core, json
cfg = _core.load_config('config/user-config.json')
print(json.dumps(cfg, ensure_ascii=False, indent=2))
"
```

- 解析失败说明配置本身坏了，**不要**用默认配置覆盖它——先备份再修：
  `cp config/user-config.json config/user-config.json.bak`
- 未知字段默认保留并告警；确需清理时先人工确认。
- 历史文件 `config/tone-history.json` 与配置相互独立，回滚代码不影响它。

### 协议回滚

新增的 MCP / CLI 字段都是**可选**字段，旧调用方继续可用：

- `get_style_prompt` 的 `context`：可选，不传就是旧行为。
- `next_turn` 的 `context`：可选，不传就是旧行为。
- `set_user_style` / `set_config` 的返回结构只新增字段，没改旧字段的含义。

因此回滚不需要额外的版本策略。

### 评测回滚

评测指标与判分标准都有版本号（报告里的 `报告 schema 版本`、每项指标的
`判分标准版本`）。口径变了就换回旧版本对照，不删历史报告。
