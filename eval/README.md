# 评测体系

PRD 第 9 章的验收指标在这里落地。核心思路是**把「生成回复」和「判分」彻底分开**：

- 判分器只读回复文件，不调用任何模型 → 确定性指标可以离线复现，CI 不需要模型额度。
- 生成与评审走可插拔的后端；没有配置后端时，需要模型的三项标为「未评测」，
  其余指标照常产出，不会因为缺后端就整个跑不起来。

## 目录

```
eval/
├── cases/
│   ├── chats.json      # 主评测集 60 条（闲聊 / 知识问答 / 代码与技术 / 情绪安慰 / 拒绝与纠错 / 长文，各 10 条）
│   ├── blind.json      # 盲测集 63 条（21 个风格各 3 条，题目来自 21 题池的均衡轮转）
│   ├── fusion.json     # 融合评测集 12 条（主风格 + 副风格，含两组冲突风格）
│   ├── redteam.json    # 安全红队 10 条（7 条转录自 references/safety.md，3 条补充）
│   └── scenes.json     # 场景自适应 10 条（代码 / 表格 / 高风险 / 排查步骤 / 情绪低落 / 危机 / 正式 / 非中文）
├── judge/              # 判分器，每个 judge 返回统一的指标结构
├── backends/           # 可插拔的模型后端
├── fixtures/
│   ├── responses/      # 存档的模型回复，文件名即用例 id
│   └── judgments/      # 人工评审结果，文件名即用例 id
├── generate.py         # 生成阶段：用后端把用例变成回复并存档
├── report.py           # 把指标渲染成对照 PRD 通过线的报告
└── run.py              # 入口
```

## 跑起来

```bash
# 只跑确定性指标（不需要任何模型）
python3 eval/run.py

# 加上需要模型评审的三项
python3 eval/run.py --backend chat_completions

# 先生成回复再评测
python3 eval/run.py --generate --backend chat_completions

# 写出报告（同时产出 .md 与 .json）
python3 eval/run.py --out eval/report.md
```

退出码：有指标未达标时返回 1，全部达标或标为未评测时返回 0。

## 后端

| 名字 | 说明 | 配置方式 |
| --- | --- | --- |
| `none` | 不评审，只跑确定性指标 | 默认 |
| `fixture` | 从 `fixtures/judgments/` 读人工评审结果 | 无需配置 |
| `chat_completions` | 任何提供 `/chat/completions` 接口的服务 | 见该文件的说明 |
| `messages_api` | 任何提供 `/v1/messages` 接口的服务 | 见该文件的说明 |
| `manual` | 终端里人工粘贴回复与勾选评审结论 | 无需配置 |

两个协议型后端都只用标准库 `urllib`，不引入第三方依赖。

## 指标与 PRD 通过线

| 指标 | PRD 通过线 | 是否需要模型 |
| --- | --- | --- |
| 助词密度 | ≥90% 落入风格区间 | 否 |
| 硬规则 | 100% 无违规 | 否 |
| 颜文字（关闭 / 开启） | 100% 符合 | 否 |
| 颜文字频率 | 符合倾向与档位 | 否 |
| 场景自适应 | 全部正确降档或关闭 | 否 |
| 安全红队 | 100% 通过 | 否 |
| 随机模式 | 重复 0 次，偏差 <5% | 否 |
| 风格盲测 | ≥80% 识别率 | 是 |
| 内容保真 | 100% 等价 | 是 |
| 融合主风格识别 | ≥70% | 是 |
| 副风格签名元素出现率 | ≥50% | 是 |

## 三处口径说明

**一、密度的容差。** PRD 的密度区间取自附录里 20–60 字的短句，按工具口径这些短句
普遍高于标称值。标定必须用 150–400 字的完整回复，而长回复上 ±0.5 次/百字的
取整误差会被误判成风格问题。所以判定带 ±0.5 次/百字容差，实测值照实报出，
报告里也会标注用了容差。`check_density.py` 本身的行为不变（严格区间），
容差只存在于评测层。

**二、长度不足的回复不计入分母。** 短于用例要求长度的回复会被单独列为「长度不足」，
既不计入密度通过率，也不算违规——它说明的是生成端的问题，不是判分端的问题。

**三、随机模式分三档。** PRD 的「重复 0 次」与「偏差 <5%」在权重不等且启用去重窗口时
数学上不可兼得（去重会系统性压低高权重风格）。所以判分器按三种情形分别断言：

- 去重窗口为 0：断言「偏差 <5%」，此档允许连续重复。
- 去重窗口 > 0 且权重均等：断言「零重复 + 偏差 <5%」。
- 去重窗口 > 0 且权重不等：断言「零重复」，偏差只作参考值。

## 加用例

编辑 `eval/cases/*.json` 即可，不需要改代码。常用字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 用例 id，同时是 `fixtures/responses/<id>.md` 的文件名 |
| `category` | 分类，仅用于主评测集的分组统计 |
| `style` | 本条期望使用的风格，密度与颜文字检查据此取区间与颜文字库 |
| `scene` | 场景标记：normal / code / table / high_risk / error_steps / low_mood / crisis / formal / non_chinese |
| `min_chars` | 回复长度下限，低于此值不计入密度分母 |
| `user_input` | 用户输入；盲测集与融合集用 `prompt` 索引题池 |

## 人工盲测

```bash
python3 eval/make_blind_sheet.py            # 生成 eval/blind_sheet.md
```

按表勾选，把结果写成 `eval/fixtures/judgments/<用例 id>.json`，内容形如
`{"choice": "S09 傲娇"}`，然后用 `--backend fixture` 跑判分即可。
